# 后端测试与验收报告

日期：2026-09-15  
环境：Windows x64、Node.js v24.14.1、SQLite WAL、Socket.IO 4.8、Vitest 3.2

## 结论

后端业务验收通过。规则、房间状态机、持久化、实时协议、并发竞争、断线恢复、12 人完整对局和本机并发性能均达到当前 MVP 验收要求。

## 自动化测试

运行命令：

```bash
pnpm test:backend
pnpm test:acceptance
```

覆盖范围：

- 18 项规则测试，穷举全部 46,656 种有序骰面。
- 跳猴概率关键点与排列不变性。
- 游客会话、房间创建/加入、设置、开始、暂停、继续、跳过、离开、房主移交和结束。
- 自定义奖品、复合奖项、奖品库存和最终状元。
- SQLite 事务、幂等投掷、快照恢复、增量事件和服务重启在线状态归零。
- HTTP、Socket.IO、公开战报、投掷分页、CSV 和限流。
- 邮箱密码注册/登录、重复邮箱、错误密码、退出吊销和默认名字。
- 登录用户跨会话统计，以及奖项频率、奖品、对局数和累计时长。
- 当前玩家断开 WebSocket 并超过宽限期后自动跳过；连续离线席位自动越过，全员离线时保留回合等待重连。

## 并发验收

- 同一回合同时提交两个不同投掷命令：仅一个成功，仅生成一条投掷记录。
- 同时提交两个相同 `commandId`：两次均返回同一个 `rollId`，数据库只有一条记录。
- 新标签页连接后旧标签页只读；新连接断开后可恢复剩余连接的写权限。
- 12 名玩家严格轮转，63 份奖品耗尽后完成当前轮和额外一整轮，共 84 次投掷后正确结束。

## 弱网与恢复验收

自动化模拟了以下场景：

- 投掷已经提交，但客户端不提供 ACK 回调。
- 结果提交后立即断线并超过离线宽限期。
- 重连时携带旧 `lastSequence`，补回投掷、离线及上线事件。
- 重连后重复发送原投掷命令，返回原结果且不重复扣奖。
- 事件历史不连续或超过 200 条时回退到完整快照。

测试过程中发现并修复了“无 ACK 回调导致服务端异常”的问题。当前测试属于应用层延迟、断线、丢确认和重复包模拟；尚未使用真实移动网络或系统级工具施加随机丢包、乱序和带宽限制。

## 本机性能基准

运行命令：

```powershell
$env:BOBING_BENCH_ROOMS='100'
$env:BOBING_BENCH_ROLLS='10000'
pnpm benchmark:server
```

结果：

| 场景 | 结果 |
|---|---:|
| 内存 SQLite 核心结算 | 10,000 次 / 1,583.8 ms |
| 核心吞吐 | 6,314 次/秒 |
| 核心延迟 p50 / p95 / p99 | 0.140 / 0.196 / 0.286 ms |
| 核心最大延迟 | 6.168 ms |
| 100 个 WebSocket 房间建连并订阅 | 160.5 ms |
| 100 房间同时投掷整批完成 | 46.2 ms |
| WebSocket 延迟 p50 / p95 / p99 | 40.545 / 42.771 / 43.067 ms |

以上为同机回环、单进程、内存 SQLite 的基准，用于回归而不是公网容量承诺。当前结果明显低于 PRD 的正常网络 1 秒同步目标；正式上线仍需在目标云主机、磁盘和移动网络上复测。

## 已知边界

- Node.js 当前仍会对内置 `node:sqlite` 输出实验性 API 警告，正式部署前建议决定是否切换稳定驱动。
- 架构目标是单实例；多实例需要 Redis/共享数据库，不属于 MVP。
- HTTPS、反向代理、生产 CORS、进程守护、在线备份及外部监控属于部署验收。
- H5 客户端与后端均已通过工作区完整构建；当前前端的 `DiceBowl` 产物超过 Vite 默认的 500 kB 提示阈值，属于后续首屏加载优化项，不影响本次功能验收。
