# 项目调研结论

调研时间：2026-09-15。

## 1. 结论

可以找到博饼开源项目和商业活动产品，但尚未发现同时满足以下条件的成熟开源方案：

- 现代 Web 技术栈。
- 真实多人房间和轮流状态。
- 服务端权威判奖。
- 掉线重连与房间恢复。
- 传统奖品库存。
- 可直接合法商用的完整素材。

因此建议自主实现联机系统，只参考已有项目的规则、表现和产品流程。

## 2. 参考项目

### funny/bobing

- 地址：https://github.com/funny/bobing
- Godot 4.7 的 3D 单机博饼项目。
- 包含物理投掷、奖项结算、单局十投、最高分、开奖记录和规则测试。
- 适合参考规则建模、骰子物理和测试用例。
- 不包含在线房间和实时服务端。
- 只有指定原创代码采用 MPL 2.0；模型、贴图、UI、音频、场景等资产保留全部权利，不能直接作为本项目商用素材。

### 中秋博饼小程序

- 地址：https://gitee.com/gongzuohao2018/mid_autumn_cake_program
- 2018 年的 mpvue + PHP/CodeIgniter 项目，采用 MIT 许可证。
- 页面包含登录、积分、排行、兑奖、关注和分享加次数等活动结构。
- 游戏、排行榜和兑奖存在测试或占位内容，缺少完整实时博饼实现。
- mpvue、Webpack 3 及相关依赖已经过时，不适合作为新项目底座。

### 中秋博饼3D

- 地址：https://apps.apple.com/cn/app/%E4%B8%AD%E7%A7%8B%E5%8D%9A%E9%A5%BC3d/id942435298
- 可用于观察 3D 骰子、碗、声音和投掷手感。
- 用户评论曾集中反馈多人、记录保存和物理稳定性问题。
- 说明真实多人玩法、可靠记录和稳定物理表现仍有改进空间。

### 商业活动模板

- 示例：https://www.deshengedu.cn/
- 常见功能包括每日次数、邀请助力、积分排行榜、多包厢和积分商城。
- 更接近营销抽奖工具，而不是亲友围桌轮流博饼。

## 3. 可形成的差异化

- 私人房间内真正按座位轮流，而不是每个人独立抽积分。
- 使用有限奖品库存，还原奖品逐渐减少的紧张感。
- 服务端权威随机与可追溯记录。
- 弱网重连和主持人控制。
- 规则模板版本化，容纳厦门、泉州等玩法差异。
- H5 和后续微信小程序玩家进入同一房间。

## 4. 调研带来的约束

- 不复用权利不清或明确限制的美术、音频、模型。
- 不在客户端产生真实中奖结果。
- 不以旧 mpvue 工程为基础升级。
- 首版不引入付费随机机会和现金兑换。
- 规则必须经过穷举测试，不能只依靠几个示例判断。
