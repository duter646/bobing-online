# 决策记录与待确认事项

## 已确认

### D-001 产品类型

- 状态：已确认
- 决策：亲友/公司私人房间的多人实时聚会游戏。
- 不采用：以积分排行和实物兑奖为核心的营销活动平台。

### D-002 发布顺序

- 状态：已确认
- 决策：先发布 H5 网页，再尝试微信小程序。
- 影响：后端和共享规则必须平台无关；小程序 UI 不要求与 H5 共用全部代码。

### D-003 首版数据方案

- 状态：已确认
- 决策：房间热状态保存在服务器内存，关键数据和快照写入 SQLite。
- 升级条件：需要多实例部署时评估 Redis；需要复杂长期查询时评估 PostgreSQL。

## 技术与实现决策

### D-004 工程技术栈

- 决策：Vue 3 + TypeScript + Vite；Node.js + Socket.IO；pnpm workspace。
- 原因：H5 开发效率高，客户端和服务端可以共享类型、规则及协议。
- 状态：已确认

### D-005 骰子表现

- 状态：已确认
- 决策：首版采用 Three.js + cannon-es 的受控轻量 3D 物理。
- 玩家能力：控制抓取位置、拖动方向和投掷力道。
- 边界：位置和方向影响轨迹、旋转和碰撞表现；过大力度还会提高服务端判定跳猴的概率。
- 概率：未触发跳猴时，力度不改变六枚骰子及其他奖项的概率。
- 兜底：低性能设备提供减少碰撞、缩短动画或直接展示结果的降级模式。
- 后续：保留“完整物理引擎直接产生结果”的实验方案，MVP 不启用。

### D-007 外部代码与素材

- Godot 项目的 MPL 2.0 代码只作为规则和测试设计参考；默认独立使用 TypeScript 重写，不直接复制。
- Godot 项目的模型、贴图、UI、音频、HDR 和场景不得使用，除非取得作者书面许可。
- 首选 CC0 素材；每个下载文件都必须登记来源页面、作者、许可证和下载日期。
- 项目保留第三方声明文件，即使 CC0 不强制署名也记录来源。
- 状态：已确认

### D-008 力度与跳猴

- 状态：已确认
- 决策：力度超过配置阈值后，跳猴概率随力度单调增加。
- 首轮参数：阈值 `0.8`、最大概率 `25%`、二次曲线；真机试玩后允许通过新规则版本调整。
- 安全边界：概率由服务端计算并抽取，客户端物理模拟只负责表现。
- 条件分布：未触发跳猴时，六枚骰子继续使用独立均匀随机结果。

## 规则决策

### D-006 默认规则预设

- 状态：已确认
- 状元优先级：状元插金花 > 六勃红 > 六勃黑 > 五红 > 五子（五黑）> 普通状元。
- 同类型比较：按照剩余骰子点数比较大小。
- 复合奖项：四进带一秀/二举时同时领取附加奖品。
- 状元结算：过程中记录最高状元，结束时由整局最高状元获得状元奖品。
- 六勃红：不通吃桌面剩余奖品。
- 结束条件：所有奖品领取完后完成当前轮，再额外完成一整轮后结束。
