# 红釉金纹博饼碗

本目录提供两套独立、自包含的 GLB 2.0。碗形与原创金色回纹、花瓣和卷云纹均由程序生成，未使用参考网站的照片作为贴图，也没有引用第三方模型或字体。

| 文件 | 三角面数 | 用途 |
| --- | ---: | --- |
| bowl-visual.glb | 27,264 | 高精度视觉模型，含 2048 × 2048 内嵌颜色及金属度/粗糙度贴图 |
| bowl-collision.glb | 2,496 | 低精度封闭陶瓷壳体，保留凹形碗内空间；蓝色材质仅供检查 |

## 尺寸和坐标

- 单位为米，Y 向上；原点为碗底支撑圈的中心，支撑面在 Y=0。
- 最大口径 0.36 m，高约 0.13024 m；内底中心在 Y=0.024 m。
- 两套模型采用完全相同的原点和比例，节点没有额外旋转、缩放或平移。
- 碰撞模型与细分轮廓的采样距离、加周向多边形弦差，估算上界约 1.39 mm。此值是几何近似检查，不能替代物理仿真测试。
- GLB 中面数按三角面统计，不是四边形面数。视觉网格在 UV 接缝处拆分顶点，但几何位置连续；碰撞网格保持焊接。

## 材质和预览

视觉材质为红色釉面陶瓷和金色装饰，共用一个 PBR 材质，通过内嵌贴图区分金属度和粗糙度，使用 KHR_materials_clearcoat 扩展。场景中建议添加环境反射，以显出釉面与描金的区别。

- preview-visual.png：斜视外观。
- preview-top.png：高角度内壁和碗底纹样。
- preview-collision.png：低模网格。

预览由生成脚本的独立 CPU 光栅器绘制，用于形体、图案和法线检查；实际 Three.js PBR 光照效果取决于项目环境、灯光和色调映射。

## 物理接入注意

GLB 是网格资产，不会自动创建物理碰撞体。碰撞模型是凹形静态壳体，不能对整只碗取一次凸包，否则碗口会被封住。

项目当前 cannon-es 对 Trimesh 提供球体、平面的窄相碰撞处理，但没有盒体/凸体对 Trimesh 的实现；现有骰子使用 CANNON.Box。因此不能把这个 GLB 直接转成一个 CANNON.Trimesh 后就期待盒形骰子正确滚动。保持现有物理引擎时，应将壳体分解为多个凸体组成静态复合碰撞；支持静态凹网格与盒体碰撞的引擎则可使用此低模网格。

游戏组件现已加载两套 GLB：视觉模型直接渲染，碰撞模型用于提取内壁轮廓并生成分段凸碰撞体。场景统一放大 20 倍，碗底支撑面位于桌面 Y=-0.32，碗口直径约 7.2 个场景单位。模型加载失败时使用相同尺度的程序化碗作为回退。

## 复现和检查

仓库根目录运行 `python tools/build_bobing_bowl.py`（需要 numpy、Pillow），再运行 `node tools/verify_bobing_bowl.mjs`。

生成检查包括：三角面数、尺寸、零面积面、焊接后的封闭性、朝向、UV 接缝处理与碰撞近似误差。加载检查使用项目安装的 Three.js GLTFLoader，验证材质与内嵌 PNG 头、并从上方向碗内多个半径发射射线，确认碗口没有盖面且碗底没有中心孔。完整检查结果见 model-report.json、loader-check.json。未将模型接入游戏执行骰子动力学测试。
